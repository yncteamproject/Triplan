# 요구사항 명세

기능 ID(M/T/S/P)와 규칙 ID(B1~B12)는 커밋 메시지 · PR · 리뷰에서 그대로 사용합니다.
요청 · 응답 형식은 [API 명세](api.md), 테이블 구조는 [ERD](erd.md)를 참고하세요.

기능 범위는 2026-09-09 회의([노션 — 디자인 검수 및 회의](https://app.notion.com/p/3d49dfafb59d81649e99d937c188e6bf))에서 확정했습니다.

## 회원 (M)

### M1 회원가입
- **입력**: 이메일, 비밀번호, 닉네임
- **처리**: 이메일 중복 검사, 비밀번호 BCrypt 암호화, role = USER로 저장
- **관련 규칙**: B8
- **인수 기준**
  - 필수값이 비거나 이메일 형식이 틀리면 400.
  - 비밀번호가 8자 미만이면 400.
  - 이미 가입된 이메일이면 409.
  - DB에 저장된 비밀번호는 평문이 아니다.

### M2 로그인
- **입력**: 이메일, 비밀번호
- **처리**: 비밀번호 확인 후 JWT 발급 (유효기간 24시간)
- **결과**: accessToken, memberId, nickname
- **관련 규칙**: B9
- **인수 기준**
  - 로그인에 성공하면 토큰이 발급된다.
  - 이메일이 없거나 비밀번호가 틀리면 둘 다 같은 메시지로 401.

### M3 내 정보 조회
- **처리**: 토큰의 사용자 정보 반환 (id, email, nickname, role, 가입일)

### M4 내 정보 수정
- **입력**: 닉네임(선택), 비밀번호(선택)
- **처리**: 보낸 항목만 수정, 비밀번호는 암호화해서 저장
- **인수 기준**: 보내지 않은 항목은 기존 값이 유지된다.

## 여행 계획 (T)

### T1 여행 계획
- **입력**: 제목, 시작일, 종료일
- **화면**: `/trips`(내 여행 목록, 없으면 빈 화면), `/trips/new`(여행 만들기: 이름 → 기간). 상세 · 편집 화면은 예정
- **처리**: 로그인한 회원을 여행의 주인으로 저장
- **관련 규칙**: B2, B5
- **인수 기준**
  - 목록에는 본인 여행만 보인다.
  - 종료일이 시작일보다 빠르면 400.
  - 다른 사람의 여행을 조회 · 수정 · 삭제하면 403.
  - 로그인하지 않으면 401.

### T2 방문지
- **입력**: 이름, 날짜, 시간 · 메모 · 이미지 URL · 순서 · 위도 · 경도 · 주소(선택)
- **처리**: 목록은 순서(`stopOrder`) 오름차순
- **관련 규칙**: B2, B7
- **인수 기준**
  - 순서가 음수면 400.
  - 다른 사람의 여행에 방문지를 추가하면 403.
  - 위도 · 경도 · 주소 없이도 방문지를 만들 수 있다.
  - 위도와 경도 중 하나만 보내면 400.
  - 위도가 -90 ~ 90, 경도가 -180 ~ 180을 벗어나면 400.
  - 주소가 255자를 넘으면 400.

### T3 이동 구간
- **입력**: 출발 방문지, 도착 방문지, 이동 수단, 출발 · 도착 시간, 비용 · 예약번호(선택)
- **관련 규칙**: B2, B6, B7, B10
- **인수 기준**
  - 도착 시간이 출발 시간보다 빠르면 400.
  - 존재하지 않는 방문지면 404.
  - 다른 사람 여행의 방문지를 출발 · 도착지로 쓰면 403.

### T4 숙소
- **입력**: 이름, 체크인, 체크아웃, 숙박비 · 예약번호(선택)
- **관련 규칙**: B2, B6, B7
- **인수 기준**: 체크아웃이 체크인보다 빠르면 400.

### T5 자동 견적
- **처리**: 여행의 이동 구간 비용 합 + 숙소 비용 합
- **인수 기준**
  - 교통비 20,000원 + 숙박비 100,000원이면 총 120,000원.
  - 비용이 비어 있거나 데이터가 없으면 0원으로 계산한다.

### T7 대중교통 경로 · 소요시간
- **입력**: 출발 방문지, 도착 방문지 (둘 다 위도 · 경도가 있어야 함)
- **처리**: 오디세이(ODsay) 대중교통 길찾기를 서버에서 호출해 경로 후보를 소요시간순으로 최대 3개 반환. 같은 좌표의 결과는 서버 메모리에 저장해 재사용 (무료 호출 하루 30건 절약)
- **관련 규칙**: B2, B10과 같은 방식(이 여행의 방문지만)
- **인수 기준**
  - 두 방문지에 좌표가 있으면 경로 후보와 소요시간 · 요금 · 환승 횟수 · 구간이 나온다.
  - 경로가 없으면 빈 목록과 200.
  - 방문지에 좌표가 없거나 출발과 도착이 같으면 400.
  - 다른 여행의 방문지이거나 남의 여행이면 403, 로그인 안 하면 401.
  - 오디세이 호출이 실패하면 502.
  - 같은 두 방문지를 다시 조회하면 오디세이를 다시 호출하지 않는다.
- **예정**: 조회한 경로로 이동 구간(T3) 만들기

### T6 · T8 (예정)

| ID | 기능 | 사용 기술 | 필요한 것 |
|----|------|-----------|-----------|
| T6 | 지도 시각화 (마커 + 경로) | 카카오맵 JS SDK | 카카오 앱 키 (방문지 위도 · 경도 · 주소는 추가 완료, [#31](https://github.com/yncteamproject/Triplan/issues/31)) |
| T8 | 환율 표시 | 한국수출입은행 환율 API (공공데이터포털) | API 키 (일 1,000회 무료) |

항공권 검색은 학생이 쓸 수 있는 무료 API가 없어 제외했습니다.

## 공유 게시판 (S)

### S1 게시글
- **입력**: 제목, 설명(선택), 공유할 여행
- **처리**: 로그인한 회원을 작성자로 저장, 상세 조회 시 조회수 +1, 목록은 최신순
- **관련 규칙**: B1, B3, B4
- **인수 기준**
  - 목록 · 상세는 로그인하지 않아도 볼 수 있다.
  - 제목이 100자를 넘으면 400.
  - 다른 사람의 여행을 공유하면 403.
  - 작성자가 아닌 사람이 수정 · 삭제하면 403.

### S2 댓글
- **입력**: 내용
- **처리**: 목록은 등록순
- **관련 규칙**: B1, B3
- **인수 기준**
  - 목록은 로그인하지 않아도 볼 수 있다.
  - 내용이 500자를 넘으면 400.
  - 작성자가 아닌 사람이 삭제하면 403.

### S3 게시글 목록 페이징
- **입력**: 페이지 번호(0부터, 기본 0), 페이지 크기(기본 10, 최대 50)
- **처리**: 최신 작성순으로 페이지 크기만큼 반환하고, 전체 게시글 수 · 전체 페이지 수 · 마지막 페이지 여부를 함께 반환
- **관련 규칙**: B1
- **인수 기준**
  - 파라미터 없이 호출하면 최신 10개와 전체 개수가 나온다.
  - 다음 페이지를 요청하면 그다음 글부터 나온다.
  - 범위를 벗어난 페이지는 빈 목록과 200.
  - 크기를 50보다 크게 보내면 50개까지만 나온다.
  - 페이지 번호가 음수이거나 크기가 0 이하이면 400.
  - 로그인하지 않아도 조회된다.

### S4 공유된 여행 상세 보기
- **처리**: 게시글에 연결된 여행의 방문지(방문 순서대로) · 이동 구간 · 숙소 · 경비 합계를 반환. 조회수는 오르지 않음
- **관련 규칙**: B1, B12
- **인수 기준**
  - 로그인하지 않아도 볼 수 있다.
  - 응답에 예약번호가 없다.
  - 없는 게시글이면 404.

### S5 공유된 여행을 내 여행으로 복사
- **입력**: (게시글 작성 · 수정) 복사 허용 여부, (복사) 시작일(선택)
- **처리**: 여행 · 방문지 · 이동 구간 · 숙소를 로그인한 회원의 새 여행으로 복사. 시작일을 주면 원본 시작일과의 차이만큼 모든 날짜를 이동. 복사할 때마다 게시글의 복사 수 +1
- **관련 규칙**: B1, B11, B12
- **인수 기준**
  - 복사 허용 여부를 안 보내고 게시글을 쓰면 허용(true)으로 저장된다.
  - 복사한 여행은 내 여행 목록에 나오고, 원본과 id가 다르다.
  - 원본 여행을 삭제해도 복사한 여행은 남아 있다.
  - 복사한 이동 구간의 출발 · 도착지가 복사된 방문지를 가리킨다.
  - 복사본에 예약번호가 없고, 비용은 그대로다.
  - 시작일을 주면 모든 날짜가 같은 간격으로 이동한다.
  - 복사를 허용하지 않은 게시글을 다른 사람이 복사하면 403 (작성자 본인은 가능).
  - 로그인하지 않으면 401.

### S6 게시글 목록의 여행 요약
- **처리**: 목록의 각 글에 연결된 여행의 기간 · 지역 · 방문지 수 · 총 경비를 함께 반환. 지역은 주소가 있는 방문지 중 방문 순서가 가장 빠른 것의 시 · 도
- **화면**: 메인 "이런 여행은 어때요?" 카드, 게시판 목록 (예정)
- **인수 기준**
  - 목록의 각 글에 기간 · 방문지 수 · 총 경비가 나온다.
  - 주소가 있는 방문지가 있으면 지역이 나오고, 없으면 비어 있다(null).
  - 방문지 · 비용이 없는 여행은 방문지 수 0, 총 경비 0.
  - 한 페이지를 조회할 때 글 수만큼 쿼리가 늘어나지 않는다.

## 여행 성향 테스트 (P)

### P1 테스트 제출
- **입력**: 선택한 유형 목록
- **처리**: 가장 많이 선택한 유형을 결과로 저장. 동점이면 마지막에 선택한 쪽 우선
- **인수 기준**
  - 답변이 없거나 빈 값이 섞여 있으면 400.

### P2 내 최근 결과
- **인수 기준**
  - 여러 번 테스트했으면 가장 최근 결과가 보인다.
  - 테스트한 적이 없으면 404.

## 비즈니스 규칙

모든 규칙은 화면이 아니라 서버에서 검사합니다. 화면에서 버튼을 숨겨도, API를 직접 호출하면 서버가 막습니다.

| # | 규칙 | 위반 시 응답 | 상태 |
|---|------|--------------|------|
| B1 | 게시판 · 댓글 · 공유된 여행 조회와 회원가입 · 로그인을 빼면 모두 로그인 필요 | 401 "로그인이 필요합니다." | ✅ |
| B2 | 여행 계획과 그 방문지 · 이동 구간 · 숙소 · 견적은 여행 주인만 접근 | 403 "접근 권한이 없습니다." | ✅ |
| B3 | 게시글 수정 · 삭제, 댓글 삭제는 작성자만 | 403 | ✅ |
| B4 | 게시글로 공유할 수 있는 여행은 본인 여행만 | 403 | ✅ |
| B5 | 여행 종료일은 시작일보다 빠를 수 없음 | 400 | ✅ |
| B6 | 이동 도착시간 ≥ 출발시간, 숙소 체크아웃 ≥ 체크인 | 400 | ✅ |
| B7 | 비용 · 방문 순서는 0 이상 | 400 | ✅ |
| B8 | 같은 이메일로 중복 가입 불가 | 409 | ✅ |
| B9 | 로그인 실패 시 "이메일 없음"과 "비밀번호 틀림"을 구분하지 않음 (가입 여부 노출 방지) | 401 | ✅ |
| B10 | 이동 구간의 출발 · 도착지는 본인 여행의 방문지만 | 403 | ✅ |
| B11 | 공유된 여행은 작성자가 복사를 허용한 경우에만 복사 가능 (작성자 본인은 예외) | 403 | ✅ |
| B12 | 이동 · 숙소 예약번호는 공개하지 않고, 복사할 때도 가져가지 않음 | — (응답 · 복사본에서 제외) | ✅ |

작성자 · 주인은 요청 본문으로 받지 않고 **토큰에서** 꺼냅니다. 그래서 다른 사람 이름으로 글을 쓸 수 없습니다.

## 결정 사항

| 항목 | 결정 | 이유 |
|------|------|------|
| 여행지 | 국내 여행 | 해외(일본)는 API 카드 등록 · 여행지 정보 재기획 부담으로 기각 |
| 인증 방식 | JWT (세션 없음) | React와 백엔드가 분리된 구조 |
| DB | PostgreSQL (Neon), 팀 공용 | 설치 없이 모두 같은 DB 사용 |
| 패키지 | `global` + 기능별(member / trip / share / traveltest), 기능 안에서 계층 | 담당 영역과 패키지를 맞춰 충돌을 줄이기 위해 |
| 작성자 · 주인 저장 | 문자열 ID가 아니라 `member_id` FK | 로그인한 회원과 연결해 본인 확인을 하기 위해 |
| 테스트 | `@SpringBootTest` + 실제 DB + `@Transactional` 롤백 | 수업(ex02) 방식과 동일, 실제 DB 동작까지 확인 |
| 로그인 실패 메시지 | 이메일 · 비밀번호 구분 없이 하나로 | 가입된 이메일을 알아낼 수 없도록 (B9) |
| 삭제 방식 | 부모 삭제 시 하위 데이터도 서비스에서 함께 삭제 ([ERD — 삭제 규칙](erd.md#삭제-규칙)) | 공용 DB의 외래키 설정을 바꾸지 않고 해결, 삭제 순서가 코드에 드러남 |
| 엔티티 값 수정 | 일반 엔티티는 `@Setter`, `Member`는 `@Setter` 없이 전용 메서드(`changeNickname`, `changePassword`) | 비밀번호 · 권한 · 이메일처럼 함부로 바뀌면 안 되는 값을 아무 데서나 바꿀 수 없도록 |

### 화면 설계에서 정한 것 (2026-10-06)

화면을 백엔드에 실제로 있는 기능에 맞췄습니다. 예전 도안과 다른 부분입니다.

| 항목 | 결정 | 이유 |
|------|------|------|
| 여행지 정보 페이지 | 보류. 헤더 메뉴는 "여행지 정보" 대신 "성향 테스트" | 백엔드와 데이터(외부 API)가 없고 담당자가 없음 |
| 여행 만들기 마법사 | 2단계(이름 → 기간). 교통편 · 숙박 · 예산 단계는 보류 | 여행 생성 API는 이름 · 기간만 받음. 교통편은 방문지 사이 구간마다 저장 |
| 로그인 | 이메일만. 아이디 · 비밀번호 찾기, 로그인 상태 유지 없음 | 로그인 API가 이메일만 받고, 토큰은 24시간 고정 |
| 마이페이지 | 닉네임 · 비밀번호 수정, 가입일, 여행 성향 결과만. 전화번호 · 성별 · 생년월일 · 탈퇴 없음 | 백엔드에 있는 항목만 (M3 · M4 · P2) |
| 성향 테스트 결과 | "결과 공유하기" 대신 "테스트 다시 하기" | 공유 기능이 없음 |
| 메인 하단 | "인기 여행지" 대신 공유된 계획 3개("이런 여행은 어때요?") | 게시판 → 상세 → 복사(S5)로 바로 이어짐 |
| 계획 카드 내용 | 지역 · 기간, 방문지 수 · 총 경비, 복사 수 (닉네임 · 날짜 · 조회수는 상세에서) | 계획을 고를 때 필요한 정보. 목록 응답에 여행 요약 추가 (S6, [#38](https://github.com/yncteamproject/Triplan/issues/38)) |
| 썸네일 | 사진 대신 미니 지도(T6 이후). 위치가 없으면 여행 기간 커버 | 이미지는 방문지 URL 입력뿐이라 대부분 비어 있음 |
| 사진 업로드 | 이번 범위에서 제외 | 저장 위치(공용 DB · 클라우드) 결정과 작업량이 큼 |
| 화면 스타일 | 폼(로그인 · 회원가입 · 마이페이지 · 글쓰기)은 로그인 페이지 스타일, 플래너 · 게시판은 디자인 가이드의 흰 카드 | 로그인 페이지를 기준 화면으로 정함 |
| 한글 글꼴 | Pretendard | 피그마의 Inter에는 한글 글자가 없음 |
